# T5, T12, and T18 implementation notes

## T5 sampling

`trialguide.llm.client.chat` keeps the existing `chat(messages, model, temperature=0,
logprobs=False)` call shape and accepts optional `seed` and `top_p`. Cache keys include all of
those settings and logs record the requested and served model, timestamp, sampling settings,
system fingerprint when supplied by an API server, and model revision when supplied by HF.
HF stochastic requests run one at a time with a scoped RNG seed; greedy requests remain
batchable. The seed is a reproducibility control, not a guarantee of identical outputs across
hardware, library versions, model revisions, or API backends. A compatible API server may ignore
seed or report a different system fingerprint. HF sampling requires the model's optional
transformers/torch stack, as before.

## T12 checker

`check_rule` uses the shared client for every sample. Vote mode accepts a temperature and base
seed; explicit seeds increment per sample. Its default remains temperature zero for existing
callers. Logprob confidence remains one greedy sample. Patient, trial, and rule identifiers are
not placed in the prompt. The checker only accepts evidence IDs present in the supplied visible
note; invalid or absent evidence makes a decisive answer unresolved with an empty evidence list.

## T18 retrieval

`keyword_retrieve`, `bm25_retrieve`, and `retrieve_trials` accept `VisibleNote` only, plus trial
records in the existing TrialGPT corpus shape (`_id`, title/text, and optional metadata). They
never open patient files, `id2queries.json`, annotations, or label buckets. Results use
`RetrievalResult(trial_id, score, trial, methods, metadata)`. The default stack rank-fuses
keyword overlap and BM25. Missing `rank-bm25` falls back to keyword matches.

MedCPT is opt-in with `use_medcpt=True`. Model IDs and immutable revisions are pinned in
`trialguide.retrieval.medcpt.MedCPTConfig`. The query uses visible sentence text in sentence-ID
order without numeric prefixes, capped at 256 tokens. Article inputs are the title/body pair
`[trial["title"], trial["text"]]`, capped at 512 tokens. The subsystem extracts final-layer CLS
vectors and uses unnormalized dot products.

The reusable index is cohort-specific and stores `article_embeddings.npy` plus `metadata.json`.
Metadata validates cohort, ordered trial IDs, a fingerprint of the full corpus, model revisions,
tokenizer settings, dimensions, dtype, and the embedding checksum. NumPy cache loading does not
require torch or transformers; they are imported lazily when encoding is needed. CPU is the
portable default, CUDA is supported, and fp16 is available for CUDA index construction/scoring.
Start with a modest batch size (for example, 16); reduce it if GPU memory is limited. CPU avoids
GPU-memory limits but can take substantially longer. A practical reusable-index flow is:

```python
from pathlib import Path

from trialguide.retrieval import retrieve_trials
from trialguide.retrieval.corpus import load_trial_corpus
from trialguide.retrieval.medcpt import (
    MedCPTConfig,
    get_or_build_corpus_index,
    make_medcpt_scorer,
)

trials = load_trial_corpus(Path("data/raw"), "sigir")
config = MedCPTConfig()
index = get_or_build_corpus_index(
    trials,
    "sigir",
    Path("data/cache/medcpt/sigir"),
    config,
    batch_size=16,
    device="auto",
    fp16=True,
)
scorer = make_medcpt_scorer(index, config, device="auto", fp16=True)
# `visible_note` must be produced by the approved DEV masking protocol.
ranked = retrieve_trials(visible_note, trials, use_medcpt=True, medcpt_scorer=scorer)
```

The `medcpt_scorer` hook also supports isolated fake-model tests. The ordinary no-index path
retains a bounded process-local article cache. No model was downloaded and no patient evaluation
was run for these implementation checks. A missing torch/transformers install leaves
keyword/BM25 results available and records an unavailable-dependency status in metadata.

### DEV retrieval evaluation

Run the aggregate-only T18 evaluation with:

```text
python -m trialguide.eval.retrieval_runner --raw data/raw --cache-dir data/cache/medcpt --device auto --batch-size 16
```

The runner loads DEV patients and DEV grades, applies the approved deterministic 40% random mask,
and reuses one cohort-specific corpus/index for SIGIR, TREC 2021, and TREC 2022. It reports macro
NDCG@10 and graded P@10 using the existing ranking API, plus macro Recall@10 over benchmark-labelled
grade-2 trials among patients with at least one grade-2 qrel. That recall is not recall over every
clinically eligible trial. Output contains aggregate metrics only. The four baseline rankings are
Keyword, BM25, MedCPT, and Keyword + BM25 RRF. It also reports the existing Keyword + BM25 +
MedCPT RRF from `retrieve_trials()` and a separate BM25 + MedCPT RRF entry point. Both fusion paths
share the equal-weight `1 / (20 + rank)` rule, candidate union, and deterministic trial-ID tie-break.
If `rank-bm25` is unavailable, existing BM25 retrieval continues to expose its keyword fallback,
and the three-way RRF continues to avoid a duplicate keyword vote. The BM25 + MedCPT-only path
fails clearly because keyword fallback cannot count as an independent BM25 rank.
