# Leakage checklist (T8)

Each item is a way test or calibration information could reach the system, and the rule that
prevents it. Review this list in every pull request that touches data, prompts or thresholds.

## Splits
- [ ] The split is by **patient**. A patient's note, trial labels and rule labels never appear in two splits. Frozen files: `splits/dev.txt`, `cal.txt`, `test.txt` (never edited; `tests/data/test_splits.py` checks their hashes). Load them with `trialguide.data.splits.load_split()`, never re-split.
- [ ] **Test patients (73) are sealed.** Nobody reads, prints or runs anything on them before T33. Code that loops over "all patients" must take a split argument and default to `dev`.
- [ ] **Calibration patients (73) are used for one thing:** fitting the risk threshold (T30). Not for prompts, not for choosing a model, not for ablation decisions.
- [ ] Prompts, few-shot examples, thresholds and code are chosen on the 37 development patients only. No calibration or test note may appear in any prompt, example or fine-tuning set.
- [ ] Trials are a shared corpus and appear in several splits. That is accepted (proposal Section 6). No test patient-trial label is used for any design decision.
- [ ] Expert rule labels (997 rows) belong to calibration and test patients only (decision M7). Development has none, so the dev set can never be tuned against them.

## Files that already contain the answer
- [ ] **`retrieved_trials.json`** holds each patient's *full note* and lists trials **grouped by their expert label** (0 / 1 / 2). Using it to pick candidates is fine for B6-style reproduction (T4), but the grouping must never be shown to or used by the system as a feature. For masked runs the system sees only the `VisibleNote`.
- [ ] **`id2queries.json`** holds keywords generated by GPT-4 from the *full* note. For masked experiments retrieval keywords (T18) must be regenerated from the visible note only. Never use the cached keywords with masked notes.
- [ ] **The annotation file** (`criterion_annotations.parquet`) contains the full note, GPT-4's explanation and the expert label for each rule. It is a reference source for scoring, not an input to any component. In particular `gpt4_explanation` must not reach a prompt.
- [ ] The `training` column of the annotation file is undocumented and is ignored.

## Masking (T10)
- [ ] Only `VisibleNote` leaves the masking module. Hidden sentences, the mask seed's hidden set and the original note stay inside it.
- [ ] Rule-targeted and evidence-targeted masks are built from the *trial rules* and *expert evidence*, which are available for scoring but must not be passed on. Logs may record which sentence ids were hidden, but a component under test may not read that log.
- [ ] Masks for calibration and test patients use independent seeds from each other and from development.
- [ ] The simulated doctor (T11) is the only component that reads the full record, and only through its quoting interface.

## Model memorisation
- [ ] TREC and SIGIR patients are public; the backbone may have seen them. The memorisation probe (T14) reports this. We rely on evidence-targeted masking and say so in the report.

## Fine-tuning (E1) and E2
- [ ] E1 teacher labels and QLoRA training use **development patients and PMC-Patients notes only** (T23). No calibration or test patient is used, and PMC-Patients notes are checked for overlap with the 183 evaluation patients.
- [ ] E2 (Indian-affiliated cases) is a separate evaluation set; its recalibration uses its own calibration part, never the main test set.

## Reporting
- [ ] Every results table states which split and which reference (expert or model-derived) it comes from, plus the config file and commit hash.
- [ ] The test set is opened **once** (T33). If it is opened again for any reason, the report says so.
